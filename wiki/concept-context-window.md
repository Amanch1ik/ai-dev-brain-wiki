# Контекстное окно как главное ограничение

Большинство best practices Claude Code выводятся из одного факта: **контекстное окно заполняется быстро, и с заполнением производительность падает**. Управление контекстом — важнейший ресурс. Формулировка Anthropic.

## Содержание

Окно держит весь разговор: каждое сообщение, каждый прочитанный файл, каждый вывод команды. Одна сессия отладки или исследования кодовой базы может съесть десятки тысяч токенов. Когда окно близко к пределу, Claude начинает «забывать» ранние инструкции и чаще ошибаться.

### Как беречь окно
- **`/clear`** между несвязанными задачами — полный сброс. «Kitchen sink session» (одна задача → другая → назад) засоряет контекст.
- **Автокомпактизация** при приближении к лимиту: Claude суммирует важное (паттерны кода, состояния файлов, ключевые решения). Тонкий контроль — `/compact <instructions>`.
- **`/rewind` (Esc+Esc)** — восстановить или суммировать от выбранной точки.
- **Субагенты** — исследование в отдельном окне с отчётом-саммари, чтобы не засорять основную сессию (см. [[pattern-writer-reviewer]]).
- Правило: если поправил Claude дважды по одному поводу — контекст засорён неудачными попытками, лучше `/clear` и более точный промпт.

Это инструментальная опора для двух смежных идей: разговорного [[method-context-management]] Уиллисона («clean slate») и конфигурационного [[method-context-engineering]] Фаулера («как можно меньше контекста»).
