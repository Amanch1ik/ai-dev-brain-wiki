# Токен-экономика агентов

Как сделать агентную разработку дешёвой: кэш префикса, изоляция контекста, роутинг моделей, гигиена сессии. Продолжение [[concept-context-window]] с денежной стороны.

## Содержание

### Базовая модель

```
cost = P_in × (1.00·T_uncached + W·T_cache_write + 0.10·T_cache_read) + P_out × T_output
      где W = 1.25 (TTL 5 мин) или 2.00 (TTL 1 час)
```

Ключевой факт из практики Manus: **среднее отношение input:output в агентах ≈ 100:1**. Значит генерация — шум, а вся стоимость сидит во входных токенах. Оптимизировать надо **prefill**, а не вывод. Отсюда весь приоритет: **cache hit rate важнее всего остального**.

Output у моделей Anthropic стоит ровно 5× input. Batch API даёт **−50%** на всё.

### Prompt caching

**Инвариант: кэш — это prefix match. Изменение одного байта инвалидирует всё, что идёт после.** Порядок рендера: `tools` → `system` → `messages`. Breakpoint на последнем блоке `system` кэширует tools и system вместе.

- Максимум **4** `cache_control` на запрос. Запись происходит **только в точке breakpoint**.
- Окупаемость при N обращениях: 5-минутный TTL окупается с **N ≥ 2**, часовой — с **N ≥ 3**. Часовой берут не ради денег, а ради **пауз** — когда трафик рваный и разрывы больше пяти минут.
- Чтение кэша **продлевает** его TTL.
- Короче минимальной длины префикса кэш **молча не пишется** — ошибки нет, просто `cache_creation_input_tokens: 0`.
  ⚠ проверить: источники расходятся в минимальных длинах по моделям (512 / 1024 / 2048 / 4096) — сверяй на своей модели.

**Что инвалидирует, по уровням.** Полный rebuild вызывают только **изменение набора инструментов** и **смена модели**. Изменение содержимого system убивает кэш system и messages, но не tools. `tool_choice` и переключение thinking можно дёргать пер-запрос, не теряя кэш tools+system.

**Тихие убийцы кэша** — чек-лист аудита:

| Паттерн | Почему ломает |
|---|---|
| `datetime.now()` в system prompt | префикс уникален каждый запрос |
| uuid / request-id в начале контента | то же |
| `json.dumps()` без `sort_keys=True`, итерация по `set` | недетерминированная сериализация |
| session/user id зашит в system prompt | нет шаринга между пользователями |
| условные секции system (`if flag: system += ...`) | каждая комбинация флагов = свой префикс |
| `tools=build_tools(user)` | tools в позиции 0 → не кэшируется вообще |

**Три правила Manus**, вытекающие из prefix-match: **стабильный префикс** (никаких посекундных таймстемпов), **append-only контекст** (никогда не модифицировать прошлые действия и наблюдения), **маскировать инструменты, а не удалять** (динамическое удаление tools — инвалидация нулевого уровня). У них разница cached vs uncached — **десятикратная**.

**Агентские обходы:**

| Ограничение | Обход |
|---|---|
| Правка system posреди сессии убивает кэш | добавить `{"role": "system", ...}` внутрь `messages[]` — префикс цел |
| Смена модели посреди сессии убивает кэш | вынести дешёвую подзадачу в **субагента** с другой моделью, основной цикл держать на одной |
| Добавление инструментов убивает кэш | **tool search** — схемы *дописываются*, а не подменяются |

**Проверка:** `usage.cache_read_input_tokens` на втором запросе должен быть > 0. Ноль при одинаковых префиксах — работает тихий убийца.

Два неочевидных подвоха: **окно поиска — 20 content-блоков назад**, а один агентский ход легко добавляет больше пар `tool_use`/`tool_result` → следующий запрос молча промахивается (лечится промежуточным breakpoint каждые ~15 блоков). И **запись кэша становится читаемой только когда начался стриминг первого ответа** — N параллельных запросов с одним префиксом все платят полную цену; при веере отправь один, дождись первого токена, потом остальные.

### Context engineering

Принцип Anthropic: найти **«наименьшее возможное множество high-signal токенов, максимизирующее вероятность нужного результата»**. У модели есть **attention budget** с убывающей отдачей.

**Context rot** — точность recall падает по мере роста числа токенов; трансформер строит n² попарных связей, внимание размазывается. Четыре формы: context poisoning (галлюцинация попала в контекст и переиспользуется), distraction (объём ломает рассуждение), confusion (лишнее влияет на ответ), clash (противоречащие фрагменты).

**Just-in-time retrieval вместо предзагрузки:** агент держит лёгкие идентификаторы (пути, URL, запросы) и подгружает контент инструментами в рантайме — аналог человеческой памяти «помню, где лежит, а не содержимое». Claude Code гибриден: `CLAUDE.md` грузится upfront, `glob`/`grep` дают навигацию в рантайме.

**Три техники на длинной дистанции:**

| Техника | Суть | Цена |
|---|---|---|
| **Compaction** | суммаризовать на подходе к лимиту, перезапустить окно с summary и хвостом | агрессивная компакция теряет тонкий, но критичный контекст |
| **Structured note-taking** | вести `NOTES.md`/`TODO.md` вне контекста | почти бесплатно |
| **Sub-agent isolation** | воркер исследует в чистом окне, возвращает **1000–2000 токенов** | ×N токенов на запуск |

Самая безопасная форма компакции — **tool result clearing**: вычищать сырые выводы инструментов глубоко в истории после того, как они обработаны.

**Context editing (API).** На внутреннем бенчмарке из 100 ходов веб-поиска: **−84% токенов**, агент вообще доходит до конца там, где иначе упирается в лимит; **+29%** к качеству само по себе, **+39%** в паре с memory tool. ⚠ Главный подводный камень: **любая чистка инвалидирует кэшированный префикс**. Поэтому параметр `clear_at_least` обязателен — не рвать кэш ради 500 токенов.

Итоговый совет самой Anthropic: **«Do the simplest thing that works.»**

### Роутинг моделей

Haiku против Sonnet — **3× дешевле**, против Opus — **5×**. Максимальная композиция экономии на входе (`Haiku + batch + cache read`) даёт **≈1% от цены uncached Opus input**.

**Проверенный продакшн-паттерн:** дорогая модель на оркестрацию и синтез, дешёвая — на веер. Связка **Opus-lead + Sonnet-воркеры** дала **+90,2%** над одиночным Opus на research-бенчмарке. При этом апгрейд модели воркера даёт больше, чем удвоение его бюджета токенов.

Официально для Claude Code: Sonnet закрывает большинство кодовых задач, Opus резервировать под сложные архитектурные решения; для простых субагентских задач указывать `model: haiku`; для agent teams — Sonnet.

**Effort — недооценённый рычаг.** `low` для воркеров и простых задач, `xhigh`/`max` — когда корректность дороже денег. Важный нюанс: зависимость немонотонная — более высокий effort часто **сокращает** число ходов и общую стоимость на агентской работе, поэтому стартовать с `high` и свипать, а не рефлекторно ставить максимум.

### Цена мультиагентности

| Метрика | Значение |
|---|---|
| Одиночный агент против чата | **≈4× токенов** |
| Мультиагентная система против чата | **≈15× токенов** |
| Agent teams против обычной сессии | **≈7×** |
| Доля дисперсии качества, объяснённая объёмом токенов | **80%** |
| Возврат воркера в контекст координатора | 1000–2000 токенов |

Из «80% дисперсии» следует отрезвляющий вывод: значительная часть выигрыша мультиагента — это **просто оплаченный compute**, а не координация. Веер без нужды не «умнее», он дороже. Тест на оправданность: задача параллелизуема **и** информация не влезает в одно окно **и** ценность результата покрывает burn. Кодинг обычно этот тест **не проходит**.

### Радикальная экономия: не пускать сырьё через модель

Workflow, потреблявший **~150 000 токенов** при прокачке определений инструментов и промежуточных данных через модель, после переписывания на code execution стал **~2 000 токенов** — **−98,7%**. Механика: промежуточные результаты (10 000 строк таблицы → 5 отфильтрованных) остаются в песочнице, в контекст возвращается только итог. Побочный бонус — персональные данные не попадают в контекст.

Родственное — **Tool Search**: пять MCP-серверов дают **55K токенов** определений, шесть — **100K+**. С отложенной загрузкой бенчмарк идёт с **~77K до ~8,7K**, сохраняя 95% контекстного окна, и точность выбора инструмента при этом **растёт** (49% → 74% на одном поколении моделей). В Claude Code все MCP-инструменты **deferred по умолчанию** — не выключать без причины.

### Гигиена в Claude Code

Ориентиры по деньгам: **~$13 на разработчика в активный день**, $150–250 в месяц, у 90% пользователей меньше $30 в день.

Что занимает контекст на старте: system prompt ~4200 токенов, project `CLAUDE.md` ~1800, skill descriptions ~450, `~/.claude/CLAUDE.md` ~320, MCP-инструменты (deferred) всего ~120. **Доминируют файловые чтения** — одно чтение среднего файла даёт 1000–2400 токенов. Отсюда прямой совет из доков: формулируй точнее («fix the bug in auth.ts»), чтобы Claude читал меньше файлов.

Изоляция воркера в цифрах: субагент прочитал **6100 токенов** файлов, вернул в главное окно **420**. Это и есть экономия.

Приёмы по убыванию отдачи:

1. **`CLAUDE.md` держать под 200 строк** — он входит в **каждый** запрос. Детальные workflow — в skills (грузятся on-demand), path-scoped правила — в `.claude/rules/`.
2. **Хуки как фильтр токенов** — самый недооценённый приём. Вместо чтения десятитысячестрочного лога хук грепает и отдаёт только совпадения: десятки тысяч токенов превращаются в сотни. Хук, ничего не вернувший, стоит **ноль**.
3. **Субагенты на verbose-операции** — прогон тестов, разбор логов, широкий поиск.
4. **`/clear` между несвязанными задачами, `/compact <focus>` внутри задачи.** Длинная сессия дорога тем, что каждый следующий запрос тащит всю историю.
5. **CLI вместо MCP, где возможно** (`gh`, `aws`, `gcloud`) — они не добавляют листинга инструментов вообще.
6. **Plan mode перед сложной реализацией** — дешевле, чем переделывать.

Команды: `/usage` (токены и стоимость с разбивкой по skills/субагентам/MCP), `/context` (что занимает окно сейчас), `/mcp` (стоимость по серверам — отключить неиспользуемые).

⚠ После `/compact` system prompt, `CLAUDE.md`, память и MCP-инструменты переинжектятся автоматически, а **список описаний skills — нет**; сохраняются только реально вызванные.

### Измерение

- **`/usage`** — локальная оценка по счётчикам токенов, может расходиться с биллингом; авторитетный источник — консоль.
- **`ccusage`** — сторонний CLI, читает локальные JSONL без API-ключа: `npx ccusage@latest daily|weekly|session|blocks`.
- **OpenTelemetry** — единственный способ получить per-user метрики в реальном времени. Метрика `claude_code.token.usage` с атрибутами `type` (`input`/`output`/`cacheRead`/`cacheCreation` — отсюда считается cache hit rate), `model`, **`query_source`** (`main`/`subagent` — цена веера отдельной строкой), `effort`, `mcp_server.name`.
- Подсчёт токенов до запроса — эндпоинт `count_tokens`. **Не использовать `tiktoken`** — это токенизатор другого вендора, недосчитывает 15–20% на тексте и сильно больше на коде.

### Чек-лист по убыванию отдачи

1. Заморозить префикс: никаких `now()`, uuid, per-user строк в system и tools; детерминированная сериализация.
2. Не менять модель и набор инструментов посреди сессии.
3. Tool search / deferred MCP — не выключать.
4. Не пускать сырые выводы в контекст: хуки-фильтры, targeted read, code execution для больших данных.
5. Субагенты на verbose-операции, модель `haiku`/`sonnet`, effort `low`.
6. `CLAUDE.md` < 200 строк.
7. `/clear` и `/compact` по назначению.
8. Роутинг: дёшево на веер, дорого на судью и синтез.
9. Мультиагент — только пройдя тест оправданности.
10. Мерить `cacheRead / input` и `query_source=subagent`.
