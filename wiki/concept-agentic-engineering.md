# Агентный инжиниринг

Проектирование системы, в которой AI-агенты становятся отдельными компонентами рабочего процесса — «почти как микросервисы, только с LLM внутри цикла принятия решений». Следующий шаг после [[concept-vibe-coding]].

## Содержание

**Ассистент vs агент.** Ассистент реагирует на конкретный запрос (объясни код, перепиши фрагмент). Агент берёт задачу целиком, сам разбивает на шаги, подключает инструменты и проходит путь до рабочего результата. «Ассистент помогает писать код, агент — решать задачу». Это конкретизация [[concept-llm-agent]].

**Вайбкодинг vs агентный инжиниринг.** Вайбкодинг — один диалог, один обмен. Агентный инжиниринг — цепочки задач (сбор данных → анализ → генерация → валидация), где каждый этап может выполнять отдельный агент. Инструменты (Cursor, Claude Code) двигаются от «напиши функцию» к оркестрации «разбей → выполни шаги → собери → провалидируй».

**Мультиагентные системы / субагенты.** Несколько агентов берут роли: один пишет код, другой ревьюит, третий ищет уязвимости. Ронахеровский workflow «задача агенту с полными правами → жди» ([[person-armin-ronacher]]) — минималистичный конец спектра; оркестрация субагентов — сложный.

**AI-native разработчик.** Спрос смещается: декомпозиция задачи для ИИ и промпт-инжиниринг ценятся выше знания синтаксиса; code review сгенерированного кода — часть инженерной культуры. Но автономность не переоценивать: **ответственность за результат остаётся на разработчике** (ср. [[concept-agentic-steering]]).

**Границы заранее.** Больше автоматизации = больше точек, где нужен человеческий контроль; правила и границы стоит прописать до публикации продукта, иначе скорость обернётся техдолгом или сбоем в проде (типичные сюрпризы вайбкода: race conditions, утечки, неоптимальные запросы, SQL-инъекции, хардкод секретов — см. [[concept-supply-chain-risk]]).
