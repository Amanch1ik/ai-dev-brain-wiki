# Workflows vs Agents

Архитектурное различие Anthropic внутри «агентных систем»: **workflows** — LLM и инструменты оркестрируются заранее заданными путями в коде; **agents** — LLM сам динамически управляет своим процессом и использованием инструментов.

## Содержание

- **Workflows** — предсказуемость и консистентность для чётко определённых задач.
- **Agents** — гибкость и model-driven решения там, где нужен масштаб и путь нельзя захардкодить. Конкретизация [[concept-llm-agent]].

### Когда (и когда НЕ) использовать агенты
Правило: **ищи простейшее решение, усложняй только при необходимости**. Часто агенты вообще не нужны — оптимизации одного LLM-вызова с retrieval и in-context примерами достаточно. Агентные системы меняют латентность и стоимость на качество — взвешивай tradeoff. Больше сложности оправдано → workflows для well-defined, agents для гибкости.

### Про фреймворки
Есть Claude Agent SDK, Strands (AWS), Rivet, Vellum — они упрощают старт (вызовы LLM, парсинг инструментов, цепочки). Но добавляют слои абстракции, скрывающие промпты/ответы, усложняя отладку, и провоцируют лишнюю сложность. Совет: **начинай с прямых вызовов LLM API** (многие паттерны — несколько строк); если берёшь фреймворк — понимай, что под капотом.

### Три принципа реализации агентов
1. **Простота** дизайна.
2. **Прозрачность** — явно показывай шаги планирования.
3. Тщательно проектируй **agent-computer interface** ([[concept-agent-computer-interface]]) через документацию и тестирование инструментов.
