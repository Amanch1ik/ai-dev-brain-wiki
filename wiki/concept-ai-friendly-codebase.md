# AI-friendly кодовая база

Код, с которым агентам легко работать: простой, стабильный, модульный, с чёткими границами. «Что хорошо человеку — хорошо и AI», но с усилением. Принципы от [[person-armin-ronacher]] (+ идея «AI-friendly code design» из Thoughtworks).

## Содержание

### Write simple code
«Делай самое тупое, что сработает» — простой код бьёт сложный в агентном контексте:
- **Функции** с ясными длинными именами вместо классов; избегать наследования и «умных» хаков.
- **Plain SQL** вместо min-max ORM: агент даёт отличный SQL и сверяет его с SQL-логами.
- **Держи важные проверки локально.** Permission-проверки должны быть на виду у AI; спрятанные в другом файле/конфиге — почти гарантия, что при новом роуте агент их забудет. Ср. ось Detectability в [[concept-ai-risk-assessment]].

### Стабильные экосистемы
LLM хороши с Go и любят Flask — стабильные экосистемы с малым churn. То же про твою кодовую базу: агент оставляет «хлебные крошки» (комментарии, почему выбран путь); бездумные апгрейды библиотек делают эти решения устаревшими. Вывод: будь **ещё консервативнее** с апгрейдами, чем раньше; предпочитай генерацию кода зависимостям. Прямая связь с [[concept-training-cutoff]].

### Выбор языка (для новых бэкендов — Go)
Почему Go по Ронахеру: явный `context`; кэширование тестов (Go сам знает, что гонять — критично для агентного цикла); «Go прост» (Rob Pike: для тех, кто не тянет сложный язык → подставь «агенты»); структурные интерфейсы (мало сюрпризов для LLM); низкий churn экосистемы. Python сложнее: «магия» (pytest fixtures, event loop), медленный boot интерпретатора тормозит агентный цикл. Фронт Ронахера: React + TanStack Query/Router + Vite + Tailwind (файловый роутер с `$` в именах путает агента).

### Рефактори вовремя
Агент тянет задачу, пока сложность не превысит порог (общий объём, что надо держать в голове). Пример: вайб-кодить фронт можно до момента, когда Tailwind-каша размазана по 50 файлам — тогда пора велеть сделать библиотеку компонентов, иначе редизайн даёт регрессии. Не рано и не поздно.

### Параллелизация
Отдельный агент не быстр, но параллельность повышает эффективность — нужно управлять общим состоянием (ФС, БД, Redis): избегать или сегментировать. Простейший shared state — ФС; второй чек-аут помогает. Инструмент к наблюдению — container-use (MCP-сервер, гоняющий эксперименты в Docker).
