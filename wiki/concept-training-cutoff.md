# Training cut-off date

Дата, на которой остановился сбор обучающих данных модели. Критична для кода: определяет, какие версии библиотек модель «знает». [[simon-willison]] сознательно учитывает её при выборе технологий.

## Содержание

Если у библиотеки был мажорный breaking change после cutoff, модель о нём не знает и будет генерировать устаревший код. (На момент статьи Уиллисон приводил для моделей OpenAI типичные даты октябрь 2023 / май 2024; у других провайдеров бывают свежее. ⚠ Значения устаревают — проверяй для конкретной модели.)

Следствия для практики:
- **Boring technology.** Уиллисон предпочитает стабильные, популярные библиотеки — по ним много примеров попало в обучающие данные. Принцип «boring technology»: инновируй в уникальном ядре продукта, для остального бери проверенные решения.
- **Свежие библиотеки — больше работы.** С библиотеками вне обучающих данных LLM тоже помогает, но нужно скармливать свежие примеры их использования прямо в промпт — это прямой мостик к [[method-context-management]].
- При запросе опций («what are options for HTTP libraries in Rust?») новые библиотеки не всплывут — и обычно это ОК, нужен самый стабильный вариант, а не самый новый.
