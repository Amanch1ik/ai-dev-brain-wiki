# Agent-Computer Interface (ACI)

Определения инструментов заслуживают столько же промпт-инжиниринга, сколько сам промпт. Идея Anthropic: вложи в **agent-computer interface (ACI)** столько же усилий, сколько индустрия вкладывает в human-computer interface (HCI).

## Содержание

Одно действие часто можно задать разными форматами (правка файла как diff или как перезапись целиком; вывод в markdown или JSON) — для человека косметика, но **для LLM форматы различаются по сложности**. Написать diff требует заранее знать число изменённых строк в заголовке чанка; код внутри JSON требует экранирования кавычек и переводов строк.

### Правила выбора формата инструмента
- Дай модели достаточно токенов «подумать», прежде чем она загонит себя в угол.
- Держи формат близким к тому, что модель естественно видела в тексте интернета.
- Убери форматный «overhead» — счёт тысяч строк, экранирование кода.

### Проектирование ACI
- **Влезь в шкуру модели:** очевидно ли, как пользоваться инструментом из описания и параметров? Хорошее определение включает пример использования, edge cases, требования к формату, границы с другими инструментами.
- Пиши описание как отличный docstring для джуниора; уточняй имена параметров.
- **Тестируй**, как модель использует инструменты (workbench), и итерируй.
- **Poka-yoke** — меняй аргументы так, чтобы ошибиться было труднее.

*Кейс SWE-bench: на оптимизацию инструментов ушло больше времени, чем на общий промпт. Модель ошибалась с относительными путями после смены директории → инструмент заставили требовать абсолютные пути, и ошибки исчезли.*
