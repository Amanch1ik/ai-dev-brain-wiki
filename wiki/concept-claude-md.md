# Эффективный CLAUDE.md

`CLAUDE.md` — файл, который Claude Code читает в начале **каждого** разговора: Bash-команды, стиль кода, правила workflow — стойкий контекст, который нельзя вывести из самого кода. Гайд Anthropic.

## Содержание

`/init` генерит стартовый CLAUDE.md по структуре проекта; дальше — итеративно уточнять. Он загружается каждую сессию ([[concept-context-window]]), поэтому **только то, что применимо broadly**; для ситуативного знания — [[method-context-engineering]] skills (грузятся по требованию).

**Держать кратко.** Для каждой строки спрашивай: «удаление этой строки заставит Claude ошибаться?» Если нет — вырезай. Раздутый CLAUDE.md → Claude игнорирует часть инструкций (важные правила теряются в шуме).

| ✅ Включать | ❌ Исключать |
|---|---|
| Bash-команды, которые не угадать | То, что Claude поймёт, читая код |
| Правила стиля, отличные от дефолтных | Стандартные конвенции языка |
| Инструкции по тестам, предпочтительный test runner | Детальную API-документацию (лучше ссылка) |
| Этикет репозитория (ветки, PR) | Часто меняющуюся информацию |
| Архитектурные решения проекта | Длинные объяснения/туториалы |
| Причуды окружения (env vars) | Пофайловые описания кодовой базы |
| Неочевидные gotchas | Самоочевидное («пиши чистый код») |

**Приёмы:** эмфаза («IMPORTANT», «YOU MUST») повышает адгезию; импорт файлов через `@path/to/import`; коммить в git (ценность накапливается со временем). Локации: `~/.claude/CLAUDE.md` (все сессии), `./CLAUDE.md` (в git, для команды), `./CLAUDE.local.md` (личное, в .gitignore), родительские/дочерние каталоги (монорепо). Если правило не срабатывает — файл, вероятно, слишком длинный; если Claude спрашивает то, что уже есть — формулировка двусмысленна. Относись к CLAUDE.md как к коду: ревьюй, регулярно чисти.

> Прямая связь с этой базой: её `CLAUDE.md`/`AGENTS.md` — ровно такой стойкий контекст; правило «кратко и по делу» применимо и к ним.
